Workspace / Benchmark

Performance benchmark

Configure the workload in the sidebar, then run a measurement pass. The engine executes each selected algorithm in Python and returns a complete timing series.

Protocol

What the engine measures

01
Wall-clock timing

Each algorithm runs against a shared workload using Python's monotonic time.perf_counter_ns() clock. Sorting uses the median of repeated timed runs; searches use the median of batched calls.

02
Shared workloads

Best, average, and worst cases are generated once per input size and shared across algorithms so comparisons remain fair. Search benchmarks always use sorted copies because Binary Search requires ordered input.

03
Q-weighted search

Q is the probability that a target is absent. Average-case search timing blends present-target and absent-target measurements by Q; best and worst search cases remain deterministic.

Workload profiles

Adaptive input sizes

Profile Used when Maximum n
quadratic Any quadratic sort is selected 500
sorting Only non-quadratic sorts are selected 3,000
searching Only search algorithms are selected 20,000

Datasets above the profile cap are evenly sampled. Input sizes above the supplied dataset are extended with deterministic offsets to model scaling without duplicate-heavy data.

Interpretation

Reading the measurements

Timings are machine-dependent. Compare algorithms within a single run rather than across machines or sessions. The Complexity reference is theoretical Big-O; the charts show measured behavior, which can differ for a particular implementation and workload.

Limits

Run boundaries

  • Maximum dataset: 20,000 values per run.
  • Runs are stateless; results are not persisted between reloads.
  • The server binds to 127.0.0.1:5000 by default.
  • Chart.js and Inter are served locally; no CDN is required.

Reading the table

Growth, not stopwatch time

Big-O describes how work grows as input size increases. A lower-order algorithm can still be slower for small inputs because constants and implementation details matter. The benchmark charts show measured wall-clock behavior for the selected workload.

Measured vs theoretical

Why the curves can differ

A shared workload can produce a different shape than the theoretical worst case. For example, Quick Sort with median-of-three pivots behaves well on reverse-sorted input. Treat the complexity table as a reference and the charts as an experiment.
